# Social anomalies — user requirements
No real kick, ban, world removal, application exit, filesystem manipulation outside mod-owned data, or connection termination as a horror mechanic. Fake disconnect is an AlertScreen whose button dismisses it; never calls disconnect. Skip when another screen is open. Real server moderation is unaffected.
Fake join adds a synthetic UUID to the viewer's TAB using vanilla player-info packet, and emits vanilla join text. Fake leave removes the same UUID and emits vanilla leave text after 600 ticks. Names currently fictional, checked against online names case-insensitively. Real player rows and authenticated chat are not touched. One phantom per viewer, no actual player or connection. Cleanup on shutdown, death or name conflict. 
Essential 1.5.2 supports NeoForge 26.3 (official changelog). Future optional client-local provider: read only the consenting local player's available friend names through a supported API, no server collection, auth tokens, private messages, external lookup, friend requests or real social actions. Fallback to fictional identities. Skin/mimic and TAB should share one synthetic identity lifetime, never use a real user's UUID for fake entries. A fake departure of an actual online player needs a separate reversible presentation layer and restoration that respects genuine server list changes. This iteration does not implement that, actual friend integration, fake bans, or linked mimic appearance. Build and multiplayer behavior unverified.

## Iteration 17
Real-player fake departure: server picks another online non-spectator at >32 blocks or in another dimension. Client receives only target UUID, verifies currently listed, then filters the rendered TAB rows for 400 client ticks. It does not remove any authenticated profile, affect world entity, permissions, chat session or server player list. If the real player leaves/unlists, the fake sequence stops without false return; on death or connection change it clears. A return message is only generated if the real player remains listed. A synthetic join now attempts a named mimic after six seconds, using the same fictional alias and existing mimic transformation; no real friend's skin or real name attached to the server-side mimic yet. No overlap with director events during synthetic join. Essential upstream main source inspected: internal RelationshipManager.getFriends() returns UUID map, public EssentialAPI has no relationship accessor. No private reflection or friend data transmission; integration deferred until a supported local opt-in adapter. Client mixin and runtime behavior need verification.

## Iteration 18 — player appearance
Replaced the husk mimic with private vanilla player spawn/update packets. Ordinary mimics have a fresh synthetic UUID and unlisted player-info entry, using an online player's name and profile properties (self fallback); the social phantom shares its UUID/profile between TAB and apparition. Fictional aliases use an online player's skin as a visual donor, not a claim that the alias belongs to that real account. Player profile texture metadata selects the vanilla wide/slim renderer. Model part flags and main arm are copied via Avatar synced data, and equipment snapshots include both hands and four armor slots. Both layers render according to source settings; cape availability depends on normal vanilla skin resolution. Movement follows existing mimic policy, with two-tick position/head updates and one-second appearance refresh. No synthetic authenticated account, no copied private Essential data. Skin resolution of signed profile properties on a synthetic UUID and animation fidelity must be tested in-game; Essential cosmetics, swing/pose synchronization and friends provider remain pending. Chase still uses its separate husk proxy. Cleanup removes only synthetic entity/profile IDs; social phantom remains listed until its own leave. No compile/game verification yet.
